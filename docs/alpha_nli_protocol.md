# BICA / ART αNLI — первый шаг E0: C0 baseline

**Статус:** создан экспериментальный запускатель C0; пилот на реальной Qwen3 ещё не проведён.

## Что и зачем

- Источник: [`allenai/art`](https://huggingface.co/datasets/allenai/art), конфигурация `anli`, `validation` (1532 примера).
- Каждое задание: два наблюдения, две предоставленные гипотезы, эталон 1/2.
- **C0** — одна генерация ответа на прямой prompt, без оценки SUPPORT/CONTRADICT/UNKNOWN, без голосования, без саморефлексии и без памяти.
- Работа агента (`bica_agent/`) не изменяется. Следующие C1–C5 должны использовать те же пары наблюдений и гипотез, ту же Qwen3 и заранее зафиксированную выборку.

## Локальный запуск (Windows, основной компьютер)

Из корня репозитория:

```powershell
python -m pip install -e ".[experiment,test]"
python -m pytest -q
python -u -m experiments.run_anli_baseline --host http://IP_ВТОРОГО_КОМПЬЮТЕРА:11434 --run-id anli_c0_pilot_01 --count 30 --offset 0 --sample-seed 42
```

Для первоначальной диагностики можно запускать `--count 5` с **другим** `--run-id`, например `anli_c0_debug_01` (не смешивать с формальным пилотом).

При прерывании той же командой возобновляется незавершённая часть. Запуски и прогнозы сохраняются в `results/anli/<run-id>/`, эта директория игнорируется Git.

## Разделение выборок

Сначала перемешиваем все 1532 индекса фиксированным `sample_seed=42`, затем выделяем непересекающиеся отрезки:

- Пилот: `--offset 0 --count 30`.
- Основное исследование: **после фиксации протокола**, `--offset 30 --count 300`.

Все конфигурации C0–C5 должны использовать те же `sample_seed`, `offset` и `count`. Нельзя выбирать задачи по результатам модели.

## Что сохраняется

- `manifest.json`: параметры, индексы, хеш содержимого выбранных заданий; он защищает от случайной смены настроек при продолжении.
- `predictions/NNNNN.json`: результат по заданию, предсказание, правильная метка (только для расчёта Accuracy, **после** вызова модели), текст ответа, время, выходные токены, число LLM-запросов.
- `summary.json`: число выполненных заданий, Accuracy по обработанным, invalid outputs, время и токены.

**Важные ограничения:** `output_tokens` — только токены генерации по `eval_count`, а не все входные и выходные токены. Версия/хеш модели Ollama, версия Git и входные токены пока не записываются автоматически; дополнить до основного запуска. `seed` повышает воспроизводимость, но не гарантирует побитовую детерминированность разных аппаратных конфигураций.

## Правила

1. **Gold не попадает в prompt, критику или память**; используется только в коде итоговой оценки.
2. Не изменять prompts после просмотра результатов основной выборки.
3. Не переносить историю между примерами.
4. Invalid response — ошибка с нулём баллов, а не пропущенный образец.
5. Если сеть или Ollama упали, обработанные задачи остаются на диске; незавершённый запрос повторится при перезапуске.
6. Не делать вывод об эффективности BICA по результатам одного C0 или по smoke-тестам.
