# BICA — ART/αNLI: полный экспериментальный контур C0–C5

**Статус:** запускатель и тесты реализованы; результаты C1–C5 на настоящей Qwen3 пока не получены.  
**Этап:** E0 завершение инфраструктуры → E1 сравнительный пилот → E2 основное исследование.  
**Версия протокола:** `BICA-ART-ANLI-C0-C5-v1`.

## 1. Что уже известно из настоящего пилота

На `allenai/art`, `anli/validation`, 30 заданий, прямой C0:

- Accuracy **24/30 = 80%** (усечённый ответ считается неправильным).
- `invalid=1`, `truncated=1`.
- Суммарное время вызовов ~501,75 c, сгенерированные токены ~21 197.
- Модель `qwen3:14b`, `think=True`, `temperature=0.6`, `num_ctx=4096`, `num_predict=2400`, `sample_seed=42`, `generation_seed=2026`, `offset=0`, `count=30`.

Это **пилот**, а не доказательство эффективности BICA. Его нужно сравнить с C1–C5 на **тех же 30 индексах**, не отбирая их по полученным правильным ответам.

## 2. Матрица конфигураций

| ID | Метод | Проверка SUPPORT/CONTRADICT/UNKNOWN | Голосование | Рефлексия |
|---|---|---|---|---|
| C0 | Прямой ответ из одного вызова | Нет | k=1 | Нет |
| C1 | Прямые независимые ответы, большинство | Нет | k=3 | Нет |
| C2 | BICA: оценка + один выбор | Да | k=1 | Нет |
| C3 | BICA: оценка + один выбор + критик | Да | k=1 | Да |
| C4 | BICA: оценка + три выбора | Да | k=3 | Нет |
| C5 | BICA: оценка + три выбора + критик | Да | k=3 | Да |

**Важно:** C1 повторяет **прямой промпт C0** с тремя различными seed. В C4/C5 оценка каждой гипотезы выполняется **один раз** перед тремя выборами. Это не три полностью независимые цепочки оценки и должно так описываться в курсовой. Рефлексия разрешает не более одного повторного цикла оценки/выбора, как в реализации агента.

Все задания здесь статические. Для `AgentConfig` установлен `history=False`; эффект памяти исследуем позже **на последовательных сценариях**, а не на αNLI. Генератор гипотез в αNLI не вызывается: гипотезы заданы бенчмарком.

## 3. Установка

Скопировать в корень существующего `bica-project` из ZIP **только новые файлы**:

```text
experiments/run_anli_suite.py
tests/test_anli_suite.py
docs/alpha_nli_full_suite.md
```

Существующие `bica_agent/core.py`, `experiments/anli.py`, `experiments/run_anli_baseline.py` **не заменяются**.

Предполагается уже установленное исправление `BICA_ANLI_C0_truncation_fix.zip` (в `bica_agent/client.py` есть `IncompleteLLMResponse`). Проверить:

```powershell
python -m pytest -q
```

При соответствии текущему прототипу должно успешно пройти **22 теста** без Ollama. Если возник `ImportError: IncompleteLLMResponse`, значит установлен старый `client.py`, а не исправленная версия из предыдущего этапа.

## 4. Проверка на 3 примерах (не основной пилот)

**Только если требуется дополнительная диагностика нового скрипта:**

```powershell
python -u -m experiments.run_anli_suite --host http://192.168.0.82:11434 --run-id anli_suite_debug_01 --count 3 --configs C0,C1,C2
```

Для такого запуска используется новый отдельный `run-id`, поэтому он не затронет результаты пилота на 30 примерах.

## 5. Запуск полноценного пилота C1–C5 с повторным использованием C0

Выполнить **из корня проекта**:

```powershell
python -u -m experiments.run_anli_suite --host http://192.168.0.82:11434 --run-id anli_ablations_pilot_01 --count 30 --offset 0 --sample-seed 42 --generation-seed 2026 --num-predict 2400 --num-ctx 4096 --configs C1,C2,C3,C4,C5 --reuse-c0 results/anli/anli_c0_pilot_01
```

`--reuse-c0` проверяет исходный `manifest.json`: должны совпадать модель, temperature, контекст, лимит генерации, seeds, индексный набор и хеш содержимого заданий. Затем импортирует **сохранённые** результаты C0. Он **не вызывает Qwen3 повторно** для этих заданий.

Каждый из C1–C5 выполняется на той же выборке. Если остановить процесс `Ctrl+C`, повторить **в точности ту же команду**: сохранённые результаты будут пропущены. При отключении сети или сбое сервера выполнение останавливается, но уже записанные задачи остаются на диске.

## 6. Что сохраняется

```text
results/anli/anli_ablations_pilot_01/
├── manifest.json                      # параметры, все индексы, хеш датасета и кода
├── comparison.json                    # сравнение конфигураций, парные тесты
├── comparison.csv                     # компактная сводка по C0–C5
├── C0/
│   ├── predictions/NNNNN.json         # импортированный baseline
│   └── summary.json
├── C1/
│   ├── predictions/NNNNN.json
│   └── summary.json
├── C2/
│   ├── predictions/NNNNN.json
│   ├── scenario_state/case_NNNNN.json
│   └── summary.json
└── C3/, C4/, C5/ ...
```

**Каждое задание сохраняется сразу после выполнения.** Итоговые сравнительные отчёты обновляются периодически и по окончании конфигурации.

Для каждого задания: метка ответа и gold (только в итоговом JSON), ответ до/после критика, статус invalid/truncated, оценки гипотез, результаты голосования, замечания критика, все завершённые LLM-вызовы с seed, временем, выходными токенами и причиной завершения. Запись `invalid` не исключается из accuracy — получает 0 баллов.

Показатели:

- Accuracy на **всех обработанных заданиях**, включая invalid и truncated как ошибки.
- 95% интервал Уилсона (интервал неопределённости доли правильных ответов).
- Среднее время, сгенерированные токены и обращения к LLM.
- Для C3/C5: исправления `wrong→right`, ухудшения `right→wrong`, два вида сохранения результата.
- Точный парный тест Мак-Немара для завершённых конфигураций на одинаковых индексах; сравнения являются **разведочными**, особенно при множественной проверке гипотез.

**Токены:** используется `eval_count` от Ollama — это генерация (включая токены thinking), а **не сумма входных и выходных токенов**. Время — сумма измеренных обращений к LLM, а не общее время работы скрипта.

## 7. Основной эксперимент — после анализа пилота

Когда все C0–C5 прошли 30 заданий и мы приняли решение о лимитах генерации, фиксируем протокол и используем **непересекающийся сегмент** `offset=30, count=300`:

```powershell
python -u -m experiments.run_anli_suite --host http://192.168.0.82:11434 --run-id anli_ablations_main_01 --count 300 --offset 30 --sample-seed 42 --generation-seed 2026 --num-predict 2400 --num-ctx 4096 --configs C0,C1,C2,C3,C4,C5
```

**Не запускать основную выборку до разбора полного пилота.** Если потребуется изменить бюджет токенов из-за высокой частоты truncation, изменить **для всех конфигураций, включая новый C0**, и использовать новый `run-id`.

## 8. Жёсткие правила исследования

1. В `make_direct_prompt` и в агент передаются **только** два наблюдения и два варианта объяснения, никогда `gold`.
2. Эпизодическая память: **один файл на один пример внутри одной конфигурации**; не переносить историю между αNLI-примерами и конфигурациями.
3. Никакого дообучения, использования правильной метки для «исправления» ответа и скрытых повторов усечённых генераций.
4. Нельзя менять промпты или исходный алгоритм между C0–C5 одного `run-id`; исходные файлы защищены SHA256 в манифесте. При обновлении кода нужно начинать отдельный запуск.
5. До основного эксперимента сохранить коммит Git. Для точной версии самой Ollama-модели отдельно записать вывод `ollama list` и номер версии `ollama --version`.
6. Не объявлять улучшение по пилоту из 30 заданий статистически подтверждённым: сначала основной набор, доверительные интервалы, парные сравнения и учёт стоимости.
7. Следующий отдельный этап: последовательные свидетельства/память. Только после него — свободная генерация (αNLG), MuSR и при необходимости DetectBench.
